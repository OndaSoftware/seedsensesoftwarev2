Go to **Data Settings → Varieties** and choose **Bulk Upload**. The dialog walks
through three steps, and the first two are downloads.

<Steps>
  <Step title="Download the CSV template">
    Shows the correct format and the required columns.
  </Step>
  <Step title="Download your existing data">
    The same template filled with what is already in the system. Use it to copy
    exact supplier and classification spellings rather than guessing them.
  </Step>
  <Step title="Upload your finished CSV">
    Pick the file and the import runs.
  </Step>
</Steps>

## When bulk upload is worth it

The three matched columns are the catch: every variety type, supplier, and
classification in the file has to be spelled exactly as it is in the system. So
the import earns its keep when you are loading **many varieties that share a
supplier and a classification** — a season's commercial material from one house —
because then you fill those columns once and copy down.

For five varieties across four suppliers, adding them one at a time is faster
than getting the spellings right in a spreadsheet.

## The four columns

| Column | Must match |
| --- | --- |
| Variety Name | Nothing — but it must be unique in your organization |
| Variety Type | One of the eight types below |
| Classification | An existing crop classification |
| Supplier | An existing supplier |

Valid variety types are Commercial, Dropped, Pre-commercial, Screening,
Slotting, Research, Experimental, and Advanced Research. Matching is
case-insensitive, so `commercial` is accepted.

There is no crop column. A variety gets its crop from its classification, which
is why the classification has to exist first — see
[Managing data settings](/data-and-sync/data-settings).

## What happens to bad rows

Rows are validated one at a time, so a bad row does not stop the import. You get
a count of both outcomes: *"Successfully uploaded 42 varieties, but failed to
upload 3 varieties."*

On the web, **Download Details (CSV)** then gives you the failed rows back with
an `Error` column explaining each one. The usual four:

- `Variety name "X" already exists` — it is already in the catalog
- `Invalid variety type: "x"` — not one of the eight
- `Classification "X" not found` — create it under Crop Classifications first
- `Supplier "X" not found` — create it under Suppliers first

Fix that file and upload it again; the rows that succeeded the first time are
already in and will be rejected as duplicates if you resend them.

<Callout variant="warning">
  Duplicate names are rejected on import, which is a feature. Two spellings of
  the same variety are painful to untangle once evaluations are attached to
  both.
</Callout>

<Callout variant="tip">
  Keep breeder numbers in the Variety Name column alongside commercial names —
  `Ruby Red (BP123)` — so both stay searchable. See
  [Add a variety](/varieties/add-a-variety) for why that matters.
</Callout>

If a file is fighting you, send it over. Getting a season's varieties in
correctly is something we would rather help with than have you fix row by row —
[contact support](/contact).
